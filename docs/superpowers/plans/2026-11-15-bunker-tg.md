# Бункер (Telegram mini-app) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Собрать Telegram mini-app «Бункер» на 2–16 игроков по ссылке, с ≥8000 смешными характеристиками, анимированными карточками и генеративными концовками.

**Architecture:** React-SPA (Vite) грузится как Telegram Web App. Чистая игровая логика (контент, раздача, сценарий, голосование, концовки) отделена от I/O и покрыта тестами. Реалтайм-комнаты — тонкий адаптер над websocket (Socket.IO); состояние комнат живёт в памяти Node-сервера, он же отдаёт статику SPA. Контент генерируется офлайн Node-скриптами в статический JSON. Визуал и анимации — GSAP/CSS.

**Tech Stack:** TypeScript, React 18, Vite, Vitest, `@twa-dev/sdk`, Socket.IO (client+server), Node (Express), GSAP, Tailwind CSS. Хостинг — GCE free-tier VM + Caddy (авто-HTTPS, sslip.io).

**Spec:** `docs/../DESIGN.md` (в корне проекта `bunker-tg/DESIGN.md`).

## Global Constraints

- Язык UI и контента — русский.
- В рантайме никакого ИИ и сторонних сетевых вызовов. Клиент ходит только на свой бэкенд (websocket). Весь контент — локальный JSON.
- Секреты (токен бота) только в `.env` на VM, в git не коммитятся. Клиент секретов не содержит — общается со своим бэкендом по websocket.
- Игроков в комнате: 2–16, ядро 4–8.
- Карточек-характеристик суммарно ≥ 8000 (распределение — §3 спеки).
- Чистая логика в `src/game/**` не импортирует React, Socket.IO или Telegram SDK (тестируемость).
- Node ≥ 20, пакетный менеджер npm.

## Review Focus

- **Один игрок в комнате / меньше мест, чем людей:** раздача и завершение игры не должны делить на ноль или зацикливаться. → тест в Task 5/9.
- **Нечётное число игроков и ничья в голосовании:** правило разрешения ничьей детерминировано. → тест в Task 9.
- **Все выжившие одного пола:** концовка про вымирание срабатывает, а не падает. → тест в Task 6.
- **Повторный вход по той же ссылке (reconnect):** игрок возвращается в свою же комнату, не создаёт дубль. → тест в Task 7.
- **Дубликаты характеристик у одного игрока:** раздача не выдаёт две карты из одной категории и не повторяет текст. → тест в Task 4.
