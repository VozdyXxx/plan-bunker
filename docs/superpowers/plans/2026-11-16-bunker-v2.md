# Бункер v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Расширить игру «Бункер»: реальные болезни, богатые катастрофа+бункер, ~300 карт навыков, god-mode админа, раскрытие видно всем, ИИ-концовка (Gemini) с фоллбэком.

**Architecture:** Расширяем текущую архитектуру (React+Vite фронт, Node+Socket.IO бэк, in-memory store). Контент генерируется оффлайн-скриптом в JSON. Логика (навыки, бункер, факторы концовки) — чистые функции с тестами (Vitest). ИИ-история — отдельный модуль на сервере с фоллбэком на шаблоны.

**Tech Stack:** TypeScript (strict), React 18, Vite 5, Vitest, Socket.IO, Express, Google Gemini REST API.

**Spec:** docs/superpowers/specs/2026-11-15-bunker-v2-design.md

## Global Constraints

- TS strict, без `any` в экспортируемых сигнатурах.
- Контент — только осмысленный текст, без кривых комбо; здоровье/фобии — реальные.
- Детерминированный seeded RNG (mulberry32) и в генераторе, и в раздаче/сценарии.
- Все мутации состояния партии — авторитетно на сервере.
- Секреты (`GEMINI_API_KEY`, токен) только в `server/.env`, не в git.
- Без AI-attribution в коммитах (правило памяти пользователя).
- UI по-русски, тёмная тема, мобильный приоритет.

## Review Focus

- Раздача из нового контента не даёт дублей карт в пределах одной партии.
- Теги здоровья (`contagious`,`infertile`,`immune`,`needs-meds`,`disabled`,`pregnant`,`fertile`) реально доходят до движка концовки.
- Сработавшие при вылете/проходе эффекты применяются ровно один раз и меняют состояние бункера.
- Админ-действия не ломают инвариант (живые ≥ мест и т.п.) и авторизованы только хостом.
- ИИ-концовка при отсутствии ключа/ошибке корректно падает в шаблонный фоллбэк, а не роняет сервер.
