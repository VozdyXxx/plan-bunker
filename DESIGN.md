# Бункер — Telegram mini-app (дизайн-документ)

Дата: 2026-11-15. Статус: на утверждение. Язык игры и контента: русский.

## 1. Зачем и для кого

Партийная игра «Бункер» внутри Telegram. Создатель комнаты кидает другу ссылку
прямо в чат, тот открывает мини-апп и играет вместе с ним — без установки,
регистрации и блокчейна. Главная фишка — **чёрно-комедийный тон**: смешные
характеристики и **генеративная концовка**, которая разыгрывает судьбу
выживших (маньяк перебил соседей; три парня не оставили потомства и человечество
вымерло; эпидемия без врача и т.д.).

«Web3» из первоначальной идеи убрано осознанно — это обычный Telegram Mini App.

## 2. Как играют (правила)

1. **Создание комнаты.** Хост жмёт «Создать», получает код и ссылку
   `t.me/<bot>/app?startapp=<код>`. Кидает её друзьям.
2. **Сбор игроков.** 2–16 человек. У каждого — случайный скрытый персонаж:
   по одной карте из категорий Профессия, Биология (пол+возраст+телосложение),
   Здоровье, Хобби, Багаж, Факт, Фобия, Черта характера, Суперспособность.
3. **Катастрофа.** Комнате выпадает сценарий (ядерная зима, вирус, нашествие и
   т.д.) и параметры бункера: сколько мест (≈ половина игроков), сколько лет
   сидеть, запасы, что внутри.
4. **Раунды.** По кругу каждый раскрывает одну свою карту и убеждает, что он
   нужен в бункере. После круга — **голосование**, кого выгнать. Повторяем,
   пока не останется ровно столько, сколько мест.
5. **Концовка.** По набору выживших генератор разыгрывает финал (см. §4).

## 3. Контент: ≥8000 характеристик

Всё генерируется **заранее, офлайн**, и кладётся в приложение статическим JSON.
В рантайме никакого ИИ и внешних вызовов — быстро, бесплатно, работает всегда.

Распределение по категориям (ориентир, итог ≥8000):

| Категория | Кол-во | Пример тона |
|---|---|---|
| Профессия | 1000 | «Дегустатор просрочки», «Коуч по выживанию, сам не выжил» |
| Здоровье | 1000 | «Аллергия на ответственность», «Здоров, но храпит как трактор» |
| Хобби | 1000 | «Коллекционирует чужие зонтики» |
| Багаж | 1200 | «Ящик истёкшей тушёнки», «Гитара без трёх струн» |
| Факт | 1500 | «Однажды выиграл суд у голубя» |
| Фобия | 800 | «Боится тишины и своих мыслей» |
| Черта характера | 700 | «Токсичный оптимист» |
| Особое/способность | 500 | «Умеет готовить из ничего» |
| Биология/телосложение | 300 | пол, возраст, «метр с кепкой» |

Источник — открытые списки карт «Бункера» для структуры и вдохновения, сам текст
оригинальный. Весь сгенерированный текст прогоняется через скил **humanizer**,
чтобы шутки звучали живо, а не «как нейросеть».

## 4. Движок концовок (ядро проекта)

Правиловый симулятор, **без ИИ в рантайме**. Вход: карты выживших + сценарий
(лет в бункере, условия, запасы). Выход: смешной нарратив из собираемых блоков.

Факторы, которые он учитывает:
- **Демография:** соотношение полов и возрастов → если продолжение рода
  невозможно, человечество вымирает (гэг из примера про трёх парней).
- **Опасные черты:** маньяк / агрессор → жертвы среди выживших.
- **Медицина:** вспышка болезни и есть ли врач/иммунитет → эпидемия или спасение.
- **Навыки и запасы:** еда, умение готовить/чинить → голод или быт наладился.
- **Психика:** фобии и характеры → конфликты, бунты, безумие.

Из десятков таких модулей собираются разнообразные финалы: сколько зашло,
сколько выжило, что их погубило или спасло, с процентом «человечество
восстановилось / вымерло».

## 5. Технические решения (мои, не обсуждённые)

- **Фронтенд:** React + Vite + Telegram Web App SDK (`@twa-dev/sdk`).
- **Реалтайм/бэкенд:** self-host на самой VM — Node + Socket.IO. Комнаты и фазы
  живут в памяти процесса, игроки синхронизируются через websocket-события.
  Отдельных облачных сервисов и аккаунтов не нужно.
- **Бот:** в @BotFather, прислан токен (будет перевыпущен, хранится в `.env` на
  VM). Бот нужен для web-app-кнопки и ссылок-приглашений, игровой логики в нём нет.
- **Хостинг:** Google Compute Engine free-tier (e2-micro, регион us-*). На VM:
  тот же Node отдаёт собранную статику SPA и websocket, перед ним **Caddy** с
  авто-HTTPS (Let's Encrypt). Домен — бесплатный `<ip>.sslip.io`.
- **Дизайн:** визуал через скилы `ui-ux-pro-max` / `impeccable`, тёмно-бункерная
  атмосфера с ламповым юмором.
- **Секреты:** токен бота — в `.env` на VM, в git не попадает. Клиент секретов не
  содержит (ходит на свой же бэкенд по websocket).

## 6. Подходы, которые рассматривали

- **Self-host Node + Socket.IO на GCE free-tier VM (выбрано).** Раз VM всё равно
  бесплатна и всегда включена — сервер отдаёт и статику, и websocket. Ноль
  сторонних аккаунтов, полный контроль, бесплатно.
- **Supabase.** Живая синхронизация без своего сервера, но ещё один аккаунт и
  ключи. Отклонено, т.к. VM и так есть.
- **Только через Telegram без бэкенда.** Дёшево, но для живой партии хрупко
  (лаги, лимиты). Отклонено.

Концовки: правиловый генератор против рантайм-ИИ. Выбран правиловый —
бесплатно, предсказуемо, работает офлайн, не нужен ещё один ключ.

## 7. Цели / не-цели / анти-цели

- **Цели:** играбельная партия на 2–16 человек по ссылке; ≥8000 смешных
  характеристик; живые генеративные концовки; приятный визуал.
- **Не-цели:** блокчейн, реальные деньги, магазин, публикация в сторах,
  рейтинги/аккаунты.
- **Анти-цели (провал, даже если работает):** скучные/однотипные
  характеристики; концовки, не зависящие от выживших; текст, читающийся как ИИ;
  необходимость что-то устанавливать кроме Telegram.

## 8. Что оставляем на реализацию

- Точные формулы голосования и ничьих.
- Схема таблиц Supabase и правила RLS.
- Конкретные тайминги раундов.
- Пулы шаблонов концовок и их веса.
- Экранные состояния и переходы (лобби → раунды → голосование → финал).

## 9. Визуал и анимации

Приоритет — «карточки персонажей, которые красиво живут на экране». Делаем через
скилы `ui-ux-pro-max` (GSAP-пресеты), `impeccable` (полировка), `humanizer` (текст).

- **Атмосфера:** тёмный бункерный интерфейс — бетон, аварийный свет, мягкое
  неоновое свечение, ламповый пост-апокалипсис с юмором.
- **Карта персонажа:** плотная карточка с категорией, иконкой и текстом;
  переворот (flip) при раскрытии, лёгкий 3D-наклон за курсором/пальцем,
  «впечатывание» новой характеристики.
- **Раскрытие карты:** анимация вскрытия с подсветкой и микро-тряской экрана.
- **Голосование:** карточки игроков собираются, счётчик голосов тикает,
  выбывший уезжает за «дверь бункера».
- **Концовка:** кинематографичная сцена-таймлайн судьбы выживших, текст
  набирается по строкам, в финале — штамп «Человечество: восстановилось N%».
- **Переходы фаз:** лобби → раунд → голосование → финал с плавными переходами,
  без резких скачков. Бережём производительность на телефоне (GSAP/CSS, без
  тяжёлых библиотек).

hyperframes в самом аппе не используется (это рендер видео); приберегаем его на
возможный промо-трейлер игры.

## 10. Зафиксированные решения

- **Хостинг:** Google Compute Engine free-tier (e2-micro, us-*), Caddy + sslip.io.
- **Бэкенд:** self-host Node + Socket.IO на той же VM (без Supabase).
- **Игроки:** ядро 4–8, поддержка до 16.
- **Тон концовок:** чёрная комедия — смерти, болезни, вымирание допустимы,
  подаются с юмором, без жестокости ради жестокости.
- **Сторонние скилы с GitHub:** не ставим без конкретной проверенной ссылки;
  установленных скилов достаточно.
